### Keras Functional API

- **What It Is**: The **Functional API** is a Keras interface for building neural networks as a **graph of layers**, offering more flexibility than the Sequential API.
- **Capabilities**:
  - **Multiple Inputs/Outputs**: Combine different data types (e.g., images + text).
  - **Shared Layers**: Apply the same layer to multiple inputs (e.g., Siamese networks for similarity tasks).
  - **Non-Sequential Data Flows**: Create complex architectures (e.g., residual connections, multi-branch models).
- **Comparison with Sequential API**:
  - **Sequential API**: Linear, like stacking blocks in one line.
    - Example: `model = Sequential(); model.add(Dense(64, activation='relu')); model.add(Dense(10, activation='softmax'))`
  - **Functional API**: Graph-based, like connecting nodes in a network.
    - Allows branching, merging, and reusing layers.
- **Advantages**:
  - **Flexibility**: Build models with intricate structures (e.g., multi-task learning).
  - **Clarity**: Explicit layer connections make debugging easier.
  - **Reusability**: Share layers across parts of the model.
- **Clarification**: The Functional API is like a circuit board, letting you wire components (layers) freely, unlike the Sequential API’s fixed wiring.

### Building a Model with Functional API

- **Basic Example** (Single Input, Single Output):
  - **Code**:
    ```python
    from keras.layers import Input, Dense
    from keras.models import Model
    # Define input layer
    inputs = Input(shape=(8,))  # e.g., 8 features
    # Connect dense layer
    x = Dense(64, activation='relu')(inputs)
    # Output layer
    outputs = Dense(10, activation='softmax')(x)  # e.g., 10 classes
    # Create model
    model = Model(inputs=inputs, outputs=outputs)
    ```
  - **Explanation**:
    - `Input(shape=(8,))`: Defines input (e.g., 8 predictors).
    - `Dense(64, activation='relu')(inputs)`: Connects a 64-node layer to the input.
    - `Model(inputs, outputs)`: Combines input and output into a model.
- **Complex Example** (Multiple Inputs, Shared Layers):
  - **Scenario**: Model with two inputs (e.g., image features, text data), processed separately, then merged.
  - **Code**:
    ```python
    from keras.layers import Input, Dense, concatenate
    from keras.models import Model
    # Define two input layers
    input_a = Input(shape=(10,))  # e.g., image features
    input_b = Input(shape=(5,))   # e.g., text features
    # Process input_a
    x = Dense(32, activation='relu')(input_a)
    # Process input_b with shared layer
    shared_layer = Dense(16, activation='relu')
    y = shared_layer(input_b)
    # Concatenate branches
    combined = concatenate([x, y])
    # Additional processing
    z = Dense(8, activation='relu')(combined)
    # Output layer
    outputs = Dense(1, activation='sigmoid')(z)  # e.g., binary classification
    # Create model
    model = Model(inputs=[input_a, input_b], outputs=outputs)
    ```
  - **Explanation**:
    - Two inputs (`input_a`, `input_b`) for different data types.
    - `shared_layer`: Applied to `input_b`, reusable for other inputs.
    - `concatenate`: Merges branches into one.
    - Outputs a single prediction (e.g., 0/1 for binary classification).
- **Example**: A healthcare model uses two inputs (MRI scan data + patient history) to predict disease risk, merging branches with the Functional API.
- **Clarification**: Building with the Functional API is like designing a custom pipeline, connecting inputs and layers like pipes in a plumbing system.

## Keras Functional API and Subclassing API

### Functional API Capabilities (Recap)

- **Key Features**:
  - **Graph-Based**: Define layers and connect them explicitly, unlike Sequential’s linear stack.
  - **Multiple Inputs/Outputs**: Handle diverse data (e.g., images + metadata).
  - **Shared Layers**: Reuse layers for efficiency (e.g., Siamese networks for comparing images).
  - **Non-Linear Flows**: Support complex designs (e.g., skip connections).
- **Use Case**: Multi-task learning, where a model predicts both disease type and severity from medical data.
- **Clarification**: The Functional API is like a modular building kit, letting you connect pieces (layers) in any pattern.

### Subclassing API

- **What It Is**: The **Subclassing API** is Keras’s most flexible interface, allowing custom model definitions by subclassing the `tf.keras.Model` class and implementing a `call()` method.
- **How It Differs**:
  - **Sequential API**: Linear stack, simple but rigid.
  - **Functional API**: Graph-based, flexible but static.
  - **Subclassing API**: Fully customizable, dynamic architecture, ideal for non-standard models.
- **When to Use**:
  - **Dynamic Architectures**: Models that change based on input (e.g., reinforcement learning).
  - **Custom Training Loops**: Control training process beyond `model.fit()`.
  - **Research/Prototyping**: Experiment with novel layers or architectures.
- **Clarification**: The Subclassing API is like coding a custom app, giving you full control over design and behavior.

### Building a Model with Subclassing API

- **Code Example** (Custom Model with Two Dense Layers):
  ```python
  import tensorflow as tf
  from keras.layers import Dense

  class MyModel(tf.keras.Model):
      def __init__(self):
          super(MyModel, self).__init__()
          self.dense1 = Dense(64, activation='relu')  # First layer
          self.dense2 = Dense(10, activation='softmax')  # Output layer

      def call(self, inputs):
          x = self.dense1(inputs)  # Pass inputs through first layer
          return self.dense2(x)  # Pass to output layer

  # Create and compile model
  model = MyModel()
  model.compile(optimizer='adam', loss='categorical_crossentropy', metrics=['accuracy'])
  ```
- **Explanation**:
  - ** `__init__`**: Defines layers (e.g., two dense layers).
  - ** `call`**: Specifies how data flows through layers (forward pass).
  - **Dynamic**: Can include conditional logic (e.g., change layers based on input).
- **Custom Training Loop Example** (Using `tf.GradientTape`):
  ```python
  model = MyModel()
  optimizer = tf.keras.optimizers.Adam()
  loss_fn = tf.keras.losses.CategoricalCrossentropy()

  for epoch in range(10):
      for x_batch, y_batch in train_dataset:
          with tf.GradientTape() as tape:
              predictions = model(x_batch)  # Forward pass
              loss = loss_fn(y_batch, predictions)  # Compute loss
          gradients = tape.gradient(loss, model.trainable_variables)  # Compute gradients
          optimizer.apply_gradients(zip(gradients, model.trainable_variables))  # Update weights
  ```
- **Explanation**:
  - `tf.GradientTape`: Tracks computations to calculate gradients.
  - Custom loop offers control over training (e.g., custom loss calculations).
- **Example**: A researcher uses the Subclassing API to build a dynamic model for reinforcement learning, adjusting layers based on game state.
- **Clarification**: Subclassing is like writing a custom recipe, defining every step of cooking (forward pass) and tweaking the process (training).

### Comparing APIs

- **Sequential API**:
  - **Pros**: Simple, quick for linear models (e.g., basic classification).
  - **Cons**: Limited to single input/output, no shared layers.
  - **Use**: Beginner projects, simple neural networks.
- **Functional API**:
  - **Pros**: Flexible, supports multiple inputs/outputs, shared layers, clear structure.
  - **Cons**: Still static (fixed graph), less flexible than Subclassing.
  - **Use**: Complex but structured models (e.g., multi-task learning).
- **Subclassing API**:
  - **Pros**: Maximum flexibility, dynamic architectures, custom training loops.
  - **Cons**: Complex, harder to debug, requires advanced knowledge.
  - **Use**: Research, non-standard models, dynamic flows.
- **Example**: Sequential for a basic image classifier, Functional for a model combining image and text, Subclassing for a custom reinforcement learning agent.
- **Clarification**: APIs are like building tools—Sequential for simple structures, Functional for modular designs, Subclassing for fully custom creations.
